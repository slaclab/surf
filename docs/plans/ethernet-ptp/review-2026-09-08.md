# Ethernet PTP design review — 2026-09-08

## Status and scope

Reviewed the [plan](README.md), current MAC bypass/FIFO/pause paths, Ethernet
byte packing, existing cocotb guidance, and primary PTP references. This is a
planning review; no PTP RTL exists and no hardware behavior was validated.
The architecture drawing now shows one instance of each block.

Follow-up: [Phase 0 experiments](phase-0-experiments.md) now reproduce the R3
counterexamples against real MAC RTL and exercise R4-R6 reference contracts.
The findings below retain their original review context; consult that result
record for current gate status and the distinction between model and RTL proof.

R1 and R2 are concrete specification errors corrected in the plan. R3-R6 are
design gates before interfaces are frozen. R7-R10 need explicit acceptance
contracts before their respective implementation phases. The additions are
requirements or proposed decisions, not claims that the problems are solved.

## Findings and closure criteria

### R1 — MAC bypass EtherType was byte-reversed

**Corrected in plan.** `EthMacRxBypass` directly compares bits 111:96;
byte 12 occupies bits 103:96. The original `x"88F7"` therefore selects wire
bytes `F7 88`. Use `x"F788"` for wire EtherType `0x88F7`.

Evidence: [classifier](../../../ethernet/EthMacCore/rtl/EthMacRxBypass.vhd),
[Ethernet package](../../../ethernet/EthMacCore/rtl/EthMacPkg.vhd), and
[existing bypass wrapper](../../../ethernet/EthMacCore/wrappers/EthMacRxBypassWrapper.vhd)
(wire `0x9000` is configured as `x"0090"`). Apply the same byte-order discipline
to multicast addresses, `localMac`, EUI-64 construction, and PTP numeric fields.

Closure test: feed independently built Ethernet bytes through the real MAC;
`88 F7` routes to PTP, `F7 88` does not. Do not construct both fixture and
expected result using the same packing helper.

### R2 — SFD capture was confused with the PTP message timestamp point

**Corrected in plan.** IEEE places the event timestamp immediately after the
delimiter. The original first-bit-of-SFD convention was one byte early.
Retain SFD detection internally and translate by one byte before calibration:
nominally 8 ns on GMII, 0.8 ns on 10G XGMII. XGMII exported offsets from the
`/S/` word's lane-0 boundary become 6.4 ns and 9.6 ns for start lanes 0 and 4.
See [IEEE interpretation, clause 7.3.4.1](https://standards.ieee.org/wp-content/uploads/import/documents/interpretations/1588-2008_interp.pdf).

Closure test: an independent timestamp oracle covers both directions, both
XGMII lanes, rollover, PHC trim, and capture-edge/`TPD_G` convention. Identical
endpoint loopbacks alone cannot expose a shared reference-point error.

### R3 — A matching header key does not prove frame identity after drops

**Open architecture gate.** Counterexample: A produces timestamp A, but its
bad-CRC frame is discarded. Valid duplicate B has the same key. B's decoded
frame arrives before its backpressured tap event. A live-table check sees one
event and one frame, and can incorrectly commit timestamp A with frame B.
Later ambiguity detection cannot retract a PHC command already executed.

The current [RX FIFO](../../../ethernet/EthMacCore/rtl/EthMacRxFifo.vhd) can
discard frames and exports an aggregate primary/bypass drop indication.
Consequently, key matching plus orphan timeout is not sufficient evidence.

Closure: prototype the actual MAC path with independently stalled event and
frame consumers, CRC and FIFO drops, identical duplicates, and overflow on the
same edge as match acceptance. Prove a retirement barrier accounts for every
possible earlier drop/event before accepting a pair. Otherwise choose explicit
per-frame association metadata in the opt-in composition while preserving
legacy public entities. Record queue bounds and the assumptions of the proof.
Timestamp capacity must follow those bounds; four entries is only a starting
value. Invalid/wrong-source floods must not generate plausible measurements.

### R4 — PHC steps need generations; watchdogs need monotonic time

**Contract added; interfaces still to freeze.** Pending Sync/delay pairs can
span a PHC step, and an already queued measurement can command a second step
using the old epoch. PHC-based timeout arithmetic also misbehaves on a set.

Closure: carry time/configuration generations through captures, association,
measurements, commands, and application events. Define same-edge priority among
step, capture, overflow, reset, and command acceptance. Flush or reject old
generations, including partially captured frames. Use unsteered ticks for ages
and watchdogs. Test positive/negative steps with all queues occupied and reset
of only one side of the PHC snapshot CDC.

### R5 — Equal-rate delay arithmetic can prevent bootstrap acquisition

**Open numerical gate.** The simple four-timestamp equation acquires a bias
of approximately half the oscillator error accumulated between Sync RX and
Delay_Req TX. A short cable, 100 ppm error, and 10 ms separation can produce
a 500 ns error, including a negative computed delay. Rejecting that delay
before estimating frequency can leave the servo unable to start.

The plan now requires either rate-ratio correction or a justified error bound
and an independent bootstrap estimator. [linuxptp's timestamp processor](https://github.com/richardcochran/linuxptp/blob/master/tsproc.c)
provides an implementation reference for correcting the local interval.
Use capture-time separation, not message completion-time separation.

Closure: sweep both oscillator-error signs, near-zero propagation delay,
delayed Follow_Up/Delay_Resp, pause, rate updates during an exchange, and
holdover reacquisition. Quantify allowable residual bias. Define delay-filter
startup and validity for an initial offset below the phase-step threshold.
Ensure stale delay causes quality expiry even while Sync continues arriving.

### R6 — Accepted TX frames cannot simply be cancelled on protocol restart

**Open lifecycle gate.** `EthMacTxFifo`, arbitration, and pause can retain a
Delay_Req after the port times out or changes configuration. A `portRst` on
one FIFO side does not establish that all downstream state is flushed. New
logic must preserve AXI valid/ready obligations during quiescence.

Closure: specify admission, queued, timestamped, response-pending, and retired
request states; separate admission/TX-event/response timers; and drain or
account for old frames without resetting primary application traffic. Test
response arrival before the delayed TX event and repeated pause refresh.
Small outstanding depth does not prevent stale responses matching after
16-bit sequence wrap. Specify maximum packet lifetime, key quarantine, and
allocator behavior on link reset, full reset, and time-generation changes.
Unlimited network replay cannot be excluded with this unauthenticated wire key.

### R7 — Servo encodings and throughput are not implementation-ready

**Further elaboration required.** The stored Q16 ppb value needs a `2^16`
factor in conversion to Q32 addends; this is now explicit. Q2.30 gains cannot
represent values of 4 or above. Broad parser interval acceptance must be
separated from the supported closed-loop operating envelope.

Closure: a table of every operand's width, binary point, range, and rounding
rule; gain/rate validity checks; cold-start filter rules; maximum command and
measurement age; and pipeline latency/resource budgets at 125/156.25 MHz.
Use serialized arithmetic where appropriate rather than assuming 128-bit
multiplies/divides fit one clock. Freeze measurable settling/overshoot limits
and supported Sync rates before calling default gains safe.

### R8 — Scheduled-event quantization, discontinuity, and result loss

**Contract expanded.** Exact PHC equality is generally impossible. Execute on
the first crossing edge and distinguish normal quantization from excessive
lateness. Space deadlines for the largest legal trimmed increment. Define
head retirement on inhibition, flush on time-generation change, and coherent
payload transfer with a destination-rate limit.

Closure: freeze a result FIFO or a one-outstanding-event software restriction;
last-execution status alone cannot preserve several queued results. Test
nonrepresentable target times, maximum rate trim, forward/backward steps,
cancel at deadline, and slower destination clocks. Multi-endpoint cancellation
is best effort: an all-or-none application requires its own interlock contract.

### R9 — Interoperability, parser limits, and quality need a concrete fixture

**Further elaboration required.** Pin a tested linuxptp release/commit and
configuration: L2 transport, E2E delay, two-step source, static source identity,
domain, minor version, multicast behavior, and message intervals. Default
intervals alone do not select that transport/profile. Retain an independent
packet capture and instrument configuration as the interoperability fixture.
The [linuxptp defaults](https://www.linuxptp.org/documentation/default/) are a
reference for interval choices, not a complete FPGA interoperability recipe.

Freeze maximum accepted PTP length and TLV count/bytes, structural TLV bounds,
message-specific flag masks, v2.1 fields (including SDO acceptance), timestamp
nanoseconds bounds, and behavior for unsupported message/profile combinations.
Skip only structurally valid unknown TLVs. Distinguish transport source port
from the grandmaster behind it; a grandmaster or time-scale change at the same
source port must invalidate old quality. Export validity separately for PHC
epoch, lock, calibration, UTC offset, and time properties; document which
combination qualifies application actions. Authentication remains later scope.

### R10 — Scope and qualification gates need ordering and measurements

**Dependency order clarified; quantitative gates still open.** Test the real
MAC in parallel with servo work, before the optional scheduler and foreign
timing registry. Qualify one GTX7 path before expanding the family matrix.
Do not make an external SimLink Timing bridge a first-endpoint dependency.

Closure: select the first board, peer, reference instrument, and synthesis
part; define resource limits, settling time, steady/peak error, observation
duration, reset sample count, temperature range, and holdover duration/error.
Measure against an independent reference, not just the endpoint's own offset
estimate. Track fixed, reset-dependent, and variable latency separately.
For clocks that may stop, specify an always-running observer or reset/lock-loss
latch that forces invalidity before consumers resume; the stopped domain cannot
monitor itself. Keep compile-supported and hardware-calibrated claims separate.
